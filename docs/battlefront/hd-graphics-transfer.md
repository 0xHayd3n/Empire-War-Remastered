# What Battlefront II Remaster can contribute to Empire at War

**Decision:** use Harrisonfog’s work as an art reference, and evaluate the separately licensed Shader Patch code for individual techniques. Do not install the Battlefront package in EaW, convert its assets, or copy its preset into Universal. Start with one native Endor comparison rather than another screen-wide sharpening filter.

## What the link contains

The [ModDB project](https://www.moddb.com/mods/hd-graphics-mod) targets *Star Wars Battlefront II* (2005). Despite the `hd-graphics-mod` URL, it is now the project page for the wider remaster. The [author’s project history](https://harrisonfog.wixsite.com/swbf2modding/about) and [ModDB file feed](https://rss.moddb.com/mods/hd-graphics-mod/downloads/feed/rss.xml) separate three things that appear together in screenshots:

## Permission is different for code and art

- **Remaster package:** the author’s [Nexus permissions](https://www.nexusmods.com/battlefront2/mods/1191) explicitly forbid converting *that file* to work in other games and require permission for use of individual assets or modification. They also prohibit re-uploading the file to other sites. No affirmative EaW grant was identified for any separate ModDB art download. The [Improved Sides page](https://www.moddb.com/mods/improved-sides-mod) identifies both custom work and models originating in other Star Wars titles; credit to the pack maker alone does not clear each underlying asset. For bespoke work, the [author lists texture and model commissions](https://harrisonfog.wixsite.com/swbf2modding/author).
- **Shader Patch code:** upstream uses the [MIT license](https://github.com/PrismaticFlower/shaderpatch/blob/9e27e09c8b17505a928bc1558faf0480a8c616ae/LICENSE). For reused upstream code, retain the applicable copyright and permission notice and check the [third-party notices](https://github.com/PrismaticFlower/shaderpatch/blob/9e27e09c8b17505a928bc1558faf0480a8c616ae/third_party.md) for the chosen files. The code license is not a license to Harrisonfog’s preset or game art.

## Recommended tests, in order

1. **Endor forest, at two distances.** Build a local recipe against the mounted EaW art, extending the [existing texture showcase](../texture-showcase.md), which already has Kuat terrain recipes but not an Endor foliage pack. Pick one bark material, leaf cluster and forest-floor layer; keep leaf opacity and distant texture levels stable. Compare the *same* AT-ST beside trees in close view and during a strategy-camera pan. Better bark up close is not a win if the canopy flickers or hides squads at gameplay zoom. Use the existing [Endor depth and motion checks](../battlefield-depth-motion.md) as a baseline.
2. **Hoth snow versus space glow.** Author two restrained scene profiles using the existing [cinematic controls](../../public/js/game/settingsvideo.js), not BF2 preset values. Judge whether bright snow retains surface detail and a dark hull remains readable beside a bright engine. Keep team colors and the HUD legible; don’t apply a second highlight roll-off over [Universal’s linear space lighting](../linear-battle-lighting.md). Try a per-map profile before considering camera-dependent regions, which may be distracting across a wide strategy view.
3. **One cruiser silhouette.** Harrisonfog’s [MC80 comparison](https://harrisonfog.wixsite.com/swbf2modding/author) shows how film reference informed a hull redesign while the original hitbox constrained it. Follow the method on one EaW-native or newly authored hull: test its outline at fleet zoom *before* investing in panel detail. Keep hardpoints, collision and damage behavior unchanged; see the local [stock-art compatibility gates](../stock-art-adapter.md).

These are proposals, not measured improvements. No mod binaries or game assets were downloaded, no archive contents or retail-EaW injector compatibility were tested, and no settings or renderer code were changed. Any prototype should be compared on/off in the [mounted Universal window](http://127.0.0.1:8590/) on both render backends.
