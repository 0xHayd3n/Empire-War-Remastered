# Light existing smoke and dust, not every sprite

**Original feasibility notes.** The implemented controls, measured particle response and limits are in [Battlefield light and materials](field-receivers.md). The [shared wind](battlefield-depth-motion.md) changes where dust goes; it doesn't tell the dust which side faces the sun or a nearby flash. This is a candidate for land battles, not a global particle brightness setting.

## Evidence

- On WebGL, [`Batch` in particles.js](../public/js/particles.js) draws ordinary alpha particles as sprite texture × authored tint. Additive color and heat displacement have separate meanings. [The particle worker's draw path](../public/js/particlesim.js) applies the archive's color/alpha tracks, random offsets and handle brightness; those are not a directional lighting field. A read-only check with `parseParticles` found the mounted stock `p_smoke_small01.alo` and `p_ATAT_Footpuff_dirt.alo` each has a world-space, blend-2, non-weather, non-heat emitter. These are good comparison fixtures, not an asset whitelist.
- On WebGPU, [`particleCode` in programs.js](../public/js/gpu/programs.js) likewise emits tinted RGB for the normal particle family. Where enabled, `SOFT_WGSL` fades opacity at opaque intersections using [`softSplit` in renderer.js](../public/js/gpu/renderer.js); the WebGL `Batch` shader has no corresponding depth input. Intersection fading is not lighting. Compare on/off **within** each backend before comparing the backends.
- Land [`onImpact` and the main draw](../public/js/game/landgame.js) already have a path for local flash lights. [`BlastField.bind`](../public/js/game/blastfield.js) selects bounded, visible lights and excludes fogged sources. [`blastlight.js`](../public/js/blastlight.js) supplies the model response. The alpha sprite shader does not currently consume these lights. WebGPU has the pass uniforms; WebGL would need shared uniform references and a safe disabled fallback. Opt-in under individual settings must not depend on the realism master secretly enabling the light producer.

## Smallest useful milestone

Identify participating emitters **before batching**. The [worker's current batch key](../public/js/particlesim.js) describes texture, blend and draw flags, not whether a puff is dust. A shared particle atlas may contain smoke, sparks and other effects. An explicit per-instance flag or distinct batch key prevents lighting unrelated sprites. Leave alpha, authored animation, fog of war, additive cores, beams, HUD and heat masks alone. Start with eligible world-space alpha emitters; don't import land sky or ground fill into space.

Use a small, bounded diffuse response around the authored brightness. The light/view angle at the center is sufficient for the puff's *overall* brightness, not its sun-facing edge. For directional shape, project the actual sun into camera axes and evaluate a broad lobe over **billboard corner coordinates**, independent of atlas coordinates and random sprite rotation. Avoid hard Lambert shading that makes each puff look like a solid ball. Add flash color with bounded world-space falloff; initially reuse the existing selected lights instead of a new shadow map or volume. Cap the work with many overlapping puffs and profile it; no performance result is implied. Extending the [space battle light compositor](linear-battle-lighting.md) to land is a separate, larger change, not a prerequisite for testing the directionality.

**Acceptance:** freeze one actual plume and keep its camera, sprite positions and exposure fixed. Reverse only the test sun: the broad highlight changes sides, the atlas artwork doesn't rotate, and opacity is unchanged. Add one visual-only land flash at a known point: compare near vs distant smoke and the first frame after it expires. An additive bolt and a heat sprite should read as before. Start from the mounted [land fixture](../tools/check-battlefield.cjs) on each backend; the existing *space* preview is a comparison pattern, not a land fixture. In a second run let the battle and camera move, and report p95 as well as the median in dense smoke. No volumetric self-shadowing or new particles in the first milestone.
