# Batch map remastering

Start in the **Universal** checkout. Ask the agent “Use map-remaster for the next desert cohort, starting with Tatooine.” The [project skill](../.agents/skills/map-remaster/SKILL.md) covers the full job through playable delivery. `/skill:map-remaster` is its Pi name when project skills are loaded. The CLI automates intake, comparison and learning; it **does not install or publish a map**.

```
node tools/map-remaster.mjs catalog --scope all
node tools/map-remaster.mjs plan --scope all
node tools/map-remaster.mjs plan --scope foc --match _MP_LAND_TATOOINE
node tools/map-remaster.mjs prep --job <id printed by plan> --planet Tatooine --places jundland-wastes,jabba-the-hutts-palace
node tools/map-remaster.mjs brief --job <id> --report <reference-report> --review <inspected-brief.json>
node tools/map-remaster.mjs trial --job <id> --slot 5 --donor sand --backend webgpu
```

Requires installed game data (`SWR_GAME` if Steam discovery fails). For captures: running [Universal](http://127.0.0.1:8590/), Chrome, Node-resolvable `playwright-core` and `pngjs` (`npm install --no-save --package-lock=false playwright-core pngjs` in the checkout root). `--help` lists arguments. `--scope` also accepts `eaw`, a Workshop ID or comma-separated IDs **highest priority first**. Do not reverse an author's playset. Catalog and plan are read-only with respect to installations and pack caches. Pause while Steam is updating; a capture refuses an older job if the mounted TED or participating terrain hashes differ. A published pack can legitimately differ from the installed sources scanned on disk. Pair the correct revisions instead of weakening the check.

**What to open.** The command prints an OS-temp path under `universal-map-remaster-v1`. Catalog lists full virtual paths (including missions); a plan contains one row per mount, jobs by content ID, failures, and a cross-map `queue` of exact material pairs ordered by coverage. `--limit` bounds planning per scope. `jobs/<id>.json` gives each TED slot's source hashes, painted/submerged counts, UV scale and rotation, suggested donor/previous review, water mode, environment names and weather. Count is by map and **mount**, not number of unique TEDs. Missing or unpainted entries remain in the job, not inflated into reusable pairs. Live construction slots come from the mounted type database, not a hard-coded Endor slot number. Replanning the same inputs rewrites the same job; changed TED, source pair, edition or order gets a different ID. Only the newest plan for a query is current, not every file left in the cache.

`node tools/map-remaster.mjs batch --plan <printed-plan.json> --limit 3` captures baselines for representative high-reach pairs in distinct eligible jobs, continues past blocked routes, and prints a receipt with results. This is a bounded scout run, not a release gate. Replan before a batch after an update.

Each capture opens a new browser context. Review `painted-sources.png` (RGB; gloss alpha is not transparency), `squad`, `command`, material `surface` and `shore` when liquid water is present. `report.json` records the actual backend/environment, pack revision, cameras and simulation guards. An audition substitutes **one** licensed native-2K material pair at its physical tile scale in this restricted session. Its scope is material selection, not final anti-tiling, canopy, measured light, plant scattering or map performance. Pixel change is visibility evidence, not a quality metric. An unreadable material, covered camera, incorrect map, changed source or failed rollback cannot promote a trial.

After inspecting a successful trial, `learn --report <path> --decision candidate|avoid --note "specific visual reason"` writes *metadata only* to `tools/remaster/materials/`. This is a deliberate source edit. Future plans attach the note to exact source pairs **only while the donor hashes and scale still match**. It is advice, not runtime permission. Contradictory notes are shown together; resolve them by use/biome. Delete a bad note and replan to undo. The seed library likewise requires paired hashes from a verified stock Endor TED. A missing/renamed/altered mod material does not become Endor grass by name. Private renders and source sheets never belong in git.

## Short path for the next land map

1. **Prepare once.** Use the smallest known scope/match. After a job is chosen, `prep --job <id> [--places exterior-slug,...]` overlaps location intake with a **fresh** mounted stock capture and reads the local scan library. Open its `prep.html`. The slot worksheet lists the actually drawn/dynamic indices, exact diffuse and bump, TED tilt, sampled grade, painted counts and an example position. The same battle supplies prop model counts, infantry positions and sites. An unpainted dynamic slot stays undecided. For queue work, `batch` creates these packets for its selected jobs. Never run both `prep` and a second identical `capture` just to retrieve the inventory.
2. **Review in parallel.** Give the location reviewer `place-candidates.json` and `brief-draft.json`; give the material reviewer the indexed stock sheet and the 256px flat albedo samples with physical repeats. The empty draft carries the exact authored skies but **no selected views, families or art decisions**. Reopen and compare each source in context. Reuse hash-checked physical analogue photos as candidates only. Search for missing locations/scans; a library miss or weak planet board is not a reason to borrow another world's appearance. The two reviews meet at the cited brief and slot ledger. One writer binds the recipe.
3. **Iterate cheaply.** `python tools/remaster/cook-polyhaven.py cook <ledger.json>` hashes all four locked channels, then re-encodes only changed DDS outputs. A colour/height change and a normal/roughness change are independent. Cook/code/tool changes invalidate the relevant private receipts; the DDS bytes must still match on disk. Losing receipts costs a recook, not correctness. `--force` gives a full reference build. One writer per pack. For example, run `REMASTER_MAP=geonosis REMASTER_CHECK=look REMASTER_LOOK_VIEWS=scarp node tools/check-yavin-remaster.cjs` for the rotating rock stratum; omit `REMASTER_LOOK_VIEWS` for squad, command, the second region, the risk view and the close pan. Each invocation starts one mounted battle, writes its own `partial-look` folder, authenticates bound slices and captures original/on/restored with HUD. A five-view Geonosis WebGPU look measured **41 s** including startup; it deliberately omits climate, perimeter and foliage clearance. Reject or revise there instead of launching three full renderer passes for every material change. An iteration report is not acceptable input to `fit`.
4. **Verify once per final candidate.** `node tools/map-remaster.mjs verify --job <id> --packet <private packet.json>` produces fresh WebGPU, WebGL and 512px WebGL reports and three reference-fit boards, plus original and damaged-donor controls. It runs in a new directory each time, never reuses release captures, and schedules additional climate captures **only** when the mounted authored phases include strong weather and a clear interval. `--workers 2` overlaps up to two suites on a capable machine; default one, especially for naturally timed weather. Geonosis, Hoth, Tatooine, Naboo and Utapau are registered; a new job needs its own route, camera and exceptional controls. Other maps keep their existing checker. After this matrix examine the boards and shipping profile; add map-specific water/foliage/construction or other reviews where applicable. `needs-visual-review` is intentional, not promotion. Keep original play if a check fails.

On this machine an instrumented Geonosis build encoded eight local DDS files in **35.6 s**. With the same inputs the incremental pass took **1.7 s** (no encodes); changing one family's normal treatment took **5.4 s** (one encode). Reverting restored every DDS and the material manifest byte-for-byte. On stock Naboo, first-time scouting, reference collection and the 22-scan shelf took **17 s** together; no direction or donor was approved. Fresh final Geonosis checks took **11 min 18 s** with one worker on this run, including all three `fit` boards, original launch and corrupt-donor fallback. A two-worker attempt failed to find a deployed army on low WebGL and was not counted as complete. These measure specific stages, not first-time art direction or total release throughput.

`matrix.json` separates time spent per check, wall time for the automated matrix, and (when given the exact prep packet) elapsed time **since scouting began**. That last clock includes waits and art iteration but excludes earlier planning and the final visual sign-off. Don't sum overlapping stages or advertise a new-map completion time from a repeat cook or re-verification.

### First visible battlefield

Keep a selected landscape behind the tactical loading screen until its full binding has been verified and applied. Use the same binding for launch and live graphics changes; do not hide the flash with a timer, turn remasters on by default, or schedule a retry after revealing a rejected binding. With the option off, skip donor preparation. With changed inputs or unsupported hardware, reveal the original and keep it.

Run `node tools/check-remaster-reveal.cjs <planet> remaster` through the mounted Universal host. It delays a real donor response for ten seconds in a clean browser context. The loading card may last longer; **no stock battlefield frame may appear**. Repeat with `original` (no donor requests), `fallback` (damaged donor, stock at reveal), and `LOOK_BACKEND=webgl` for the WebGL path. Register the actual host route when adding a map. The release checker records `firstBattlefield` from the main camera’s draw as the card uncovers it, before later play/fit checks; `fit` rejects a missing or wrong launch receipt. Select the low texture tier **before** loading, not by switching from original after reveal.

## Planet identity

`references` actively searches the official Star Wars sitemap, Databank, galleries and indexed articles for the named planet. Open its OS-temp board: actual downloaded images, source pages, captions and hashes. The search is bounded and cached per planet, not repeated for every material. Catalog/plan and original captures remain offline-capable; bounded `batch` gathers references with baselines. An unknown planet requires `--planet`. An empty search is a failure, not permission to pick the nearest Endor donor. Caption coverage can be wrong: an interior described as being on a jungle moon is not a vegetation reference.

When the exact job already has a place-first brief, `references --job <id>` reopens the inspected board after hashing the private image bytes. Use `--refresh --places <comma-separated-location-slugs>` for a new candidate search. See [Clash on Tatooine](tatooine-remaster.md) for a worked example.

`brief` takes the printed job report and a JSON review. Use the [Yavin example](../tools/remaster/directions/d96aa07683839825c24b8653663e554a88948f6d4e2ff1a198d77b426f1bb03e.json) for the schema: exact `job`, `planet`, at least ten distinct inspected, place-first environment `views` for new briefs (the five-view Yavin brief predates this rule) (`page`, `image` = candidate `directUrl`, `sha256`, `visible`); separate `ground`, `foliage` and `landmark` decisions, each with a rejected alternative and evidence hashes; and `uncertain`. `landUse.natural`, `.built` and `.transition` record what belongs in each setting (or its observed absence), with specific evidence hashes. Between them they must cite five relevant views. Multiple crops of one shot, orbit views, and interiors that do not show exterior terrain do not count. Inspect pixels at both ground and landscape scale. Record `subject: landscape|building|settlement-edge`, `people: none|incidental-native`, and a distinct `settingCue` per frame; explain `nativeContext` for the latter. Start with named location exteriors, settlement plans and wide landscape photos. Field photographs of a documented filming location may establish physical terrain, not fictional architecture. Cast scenes, fights, spacecraft showcases, portraits, duplicate crops and orbital planet views are not admissible even with accurate captions. A search result is only a lead; check the image before it goes on the reviewed board. On barren planets record the observed absence of vegetation. For a mod-specific world or weak board, supplement with author/production references: add `localFile` pointing to the actual privately downloaded still and cite its HTTPS page and image. An empty-search failure report can be used with these manual references. Do not infer specifics missing from the images. Preserve mod direction where canon no longer describes that version.

`brief` checks the selected bytes and writes only the source URLs, hashes and decisions to `tools/remaster/directions/<job>.json`. With no brief, `trial` gathers the board then stops, and `learn` cannot promote a candidate. A direction is not a licence or release approval. Record direct observation separately from the licensed donor chosen to interpret it. For a composed release, `fit --job <id> --report <mounted report>` creates an offline board with the reference images and original/remastered/restored HUD-on views; compare silhouettes, floor transitions, skyline and landmark clearance, not average color. Its adapter expects `kind: composed-landscape`, job ID, active status, squad/command and second-region views, per-view rollback and `<view>-{original,remaster,restored}.png`. A material trial cannot stand in for this check.

### Native 2K Poly Haven terrain

For a complete land remaster, `donors --job <id> --query "compacted forest dirt, fine grit; no paving"` searches the official Poly Haven texture catalog after the planet brief. Compare candidate thumbnails **and flat diffuse samples** to the cited local environment views. Record accepted families, actual TED and live construction slots, physical repeat, natural/built use, visible reason and reference hash in `tools/remaster/terrain/<job>.json`. Unknown use defaults to natural, not concrete. If there is no defensible donor, block the release and keep the original playable. Existing accepted Endor remains separate.

Survey where each slot is painted across the whole field. If one tile occurs at a building and in the wild, give it an explicit reviewed apron tied to a mounted landmark and an organic fallback outside. Dynamic concrete is permitted only for actual building-paint cells. Flat ground, a texture name, proximity to a prop, and five pictures of the same hangar do not establish industrial use. Capture both a built control and a natural example of the ambiguous slot in the composed gameplay view.

`python tools/remaster/cook-polyhaven.py lock <review.json>` explicitly records the same asset's first-party **2K** diffuse, OpenGL normal, displacement and roughness sources, native dimensions and content pins. `cook <review.json>` verifies them and packs BC3 RGB+height and normal+roughness with 12 mips. Albedo is the scan itself. Regenerate the map binding after inspecting the cook. `fit` rejects partial/stock-tinted terrain: its mounted `terrainSources` receipt must match every drawn TED slot and the actual bytes of both uploaded atlas slices at the current tier; `groundUse` counts the actual geometry corners, including zero unauthorized built assignments. Reference and production imagery have separate licences; gameplay never fetches the website.

### Land map outskirts

Every **new or remastered land map** needs a reviewed horizon. `plan` records `outskirtsIntake`: actual rectangular terrain span, camera-pivot bounds, margins, rim heights, holes and submerged rim vertices. Do not enlarge the TED, move the camera stops inward, change zoom/far clipping, reveal fog, or place gameplay props outside the map. For a new board, keep its designed bounds and take the same mounted baseline before dressing its exterior.

1. Pan outward to all four stops and corners. Separate a real gap against the backdrop from fog of war, baked shade or shoreline. In `brief`, record `outskirts.treatment` (`flat`, `foothills`, `mountains`, `coastal` or `authored`), the observed `skyline`, intended `join`, a rejected alternative, at least two inspected reference hashes, and `foliage` (reviewed living class IDs, or `[]`). Don't infer mountain ranges from a planet label. If the existing horizon works, retain it and show it at the limits.
2. Follow the *drawn terrain perimeter*, including corners and elevation, not the smaller playable rectangle. For plains, extend the native substrate, density and open spaces until no cut edge is visible; bare flats need no trees. For relief, use licensed, pinned Poly Haven assets or deterministic hills with irregular saddles, a foreground-to-distance scale and a natural skyline. Continue only evidenced foliage; reuse approved donor silhouettes, chunk static stands, and skip empty roles. At a wet or cut-out rim review the actual shoreline/void and reflection first; never cap it with a generic dry skirt. If no compatible treatment is verified, keep the original and block the new release.
3. `fit` needs a mounted `outskirtsAudit` and the sixteen HUD-on `outskirts-<direction>-<maximum|oblique>.png` views. Look both outwards and along the join. Inspect the **whole** view for a straight rim, texture stripes, density jumps, horizon repetition or a hill blocking a landmark. In matched frozen frames toggle the scenery only; alternate contrasting backdrops behind the real depth-tested scene to find uncovered ground pixels. Test the patch that ought to be ground, not legitimate sky above a skyline. Capture original and restored, verify the camera and world guards, and repeat on WebGPU, WebGL and low textures. The FoC Yavin adapter lives in `tools/remaster/mounted-outskirts.cjs`; choose an appropriate oblique angle and ground window on the next board, not Yavin's by rote. `YAVIN_OUTSKIRTS_ONLY=1 node tools/check-yavin-remaster.cjs` runs just this mounted review. `node tools/test-scenic-ring.mjs` checks the dry rectangular generator, not an unreviewed planet.

## Foliage evidence and zoom continuity

Open the inspected place references before choosing any plant (ten for a new brief; the accepted Yavin brief predates that rule). Review crown shape, trunk habit, understory, low cover, open ground and transitions. In `foliage.review`, cite the inspected hashes per growth form and zone, distinguish what is visible from the licensed analogue, and choose **replace, retain or absent**. Describe the variation you can defend: for example, several leaf shapes in separated clumps rather than five tree species inferred from one silhouette. A sparse or barren world need not load a vegetation pack. Put apron, travel, wet/dry and build-site exclusions in the review. Keep reference photos out of runtime art.

Plan roots in world space and cache habitat decisions across pans. In each visible class, spend detailed geometry only where it reads; downgrade every other eligible root to a bounded cheaper representation of the *same plant*. For cutouts inspect both the side **and the top** from near-horizontal to overhead views, including mip/alpha coverage. Offscreen, script-hidden and genuinely excluded plants need not be drawn. Preserve player foreground fade, fog, sun casters and rollback. Never hide a whole layer at a camera-distance threshold or repair visibility with unbounded full-resolution draws.

`fit` requires a `foliageAudit` matching the living classes in the reference brief: same submitted roots inside a fixed world window at squad, intermediate, command, and the actual camera maximum, then return; compare HUD-on class-on/class-off images to catch invisible proxies. Where a class is absent, give the visible control and zero allocated/drawn instances instead. Count duplicate roots, triangles, actual draws, peak live slots, capacity and uploaded range separately. Size near/far/variant streams from demand; no per-variant copy of the whole world's tree list. A static camera must not republish unchanged matrices. On GL trace `bufferSubData` while zooming/panning and reject uploads beyond the live prefix. On WebGPU check the storage range for the actual draw. Budget failure must simplify the representation, not remove the roots. Gate native WebGPU, WebGL and the low tier; performance claims require a separate measured pan/combat profile.

## Renderer controls from Endor

Preserve shared engine fixes rather than adding per-map copies. Pick controls by the feature being changed and repeat them on the **new** mounted board; Endor captures are regression controls, not approval for another world.

| Change or symptom | What to compare |
|---|---|
| Dark triangle lines or a black band | Separate contact from baked shelter, direct sun and fog. With contact enabled the cliff must not occlude itself, but units and foliage must retain contact and cast shade. `check-endor-cliff-contact.cjs`, `check-terrain-shade.cjs`. |
| Texture seams vs sky leaks | Compare high-frequency contrast in donor overlaps (`check-endor-tile-lines.cjs`). For actual coverage switch between two background colors under a frozen close patch, AA on/off (`check-land-sky-cracks.cjs`); stitch its perimeter, don't cover a crack by darkening it. Check the outermost normal on a slope. |
| Ground, armor and crowns | Downward reflections sample local ground, upward reflections sample sky, gloss stays material-owned (`check-land-unit-reflections.cjs`). Compare foreground fade on/off against a unit, separately from the sun caster. Never make the whole canopy disappear at height. |
| Water, ice or lava | Check clipped shore geometry, rotated flow, bed/sheet and first reflection after resurfacing/backend switch. An interrupted mirror pass must restore target/visibility. Cull reflections when liquid is out of view; cull for the mirror's own camera when visible. Dry terrain gets no liquid pass. |
| Hitches on a pan | Test main and mirror frustum culling vs full draw; reuse unchanged placement, lighting and relief cells, sample distinct donors once, and avoid dirtying invariant indices/corners. Compare cached geometry **and shading** against cold rebuilds on a scrolling route. Keep sky reflection filtering off the main thread and verify the worker produces the same atlas (`check-ultra-relief-cost.cjs`). `test-terrain-visibility.mjs`, `test-relief-scroll.mjs`, `test-relief-taps.mjs`, `check-endor-pan-cost.cjs`. Measure upload range and rebuilds at close, command and overview, not just a single FPS counter. |

## Substrate, light and weather

Before choosing scans, identify a material that should carry across more than one place: for example wind-deposited sand, unbroken snow, or one forest-soil horizon. Cite at least two inspected settings. Separate observations about grains or geology from those about shadow, sky color, dust, wetness and exposure. Name exceptions where substrate really changes. Do not white-balance the game to a photograph, tint the whole scene, or make every planet uniformly colored.

New briefs require a `climate` section ([Tatooine example](../tools/remaster/directions/801c35a32439b92bb81d9f45c3aa6b405dc260362096156eb42e25ae84acd9e5.json)): `substrate`, `lighting`, `exceptions`, inspected `evidence`, actual `skies`, and two reviewed `pairs` in different regions. Each uses a fixed HUD-on camera, two 25×25 ground-only windows, their basis and a local tolerance, not a screen average. Inspect real units at squad height as well as wider ground. Keep foreground grain, relief, real light/dark faces, remaining props and non-playable surroundings visible. A number cannot approve an image.

For diagnosis, hold **only** diffuse RGB constant while retaining the height bytes, normal/roughness, material weights, sun, sky, fog and authored weather. Compare the same screen windows with real diffuse restored. `fit` rehashes and measures the actual screenshots under each named environment. If a real clear interval and substantial weather both occur, capture both; do not change the clock or weather strength to manufacture a better frame. For Tatooine run the mounted checker normally with `REMASTER_MAP=tatooine`, then with `REMASTER_CHECK=climate REMASTER_WEATHER=clear` on that same backend/tier. A different weather *scenario* needs an independent mounted session, not relabeling the current simulation. Keep a binding in review if that route is not implemented. Stock still works.

For an isolated terrain comparison against the authored lighting, keep **Immersive weather → Original sky** on both sides. The default generates weather skies on all outdoor land maps, independent of the landscape switch. Review the composed result separately with the [weather library](immersive-weather.md) active under that map’s real forecast.

## Patch and blend review

Start at the reported camera with real troops. Inspect the previous layout at command distance, then pan across the same transition at squad height. Identify which material boundary has a physical explanation (wear, canopy, drainage, exposed rock, a curb or apron) and which just traces the editor brush. Review at least one other region. Choose the expected variation and limits **for those places** before tuning; a uniform dune or an abrupt masonry edge is not an error just because a jungle clearing needs softer transitions.

`plan` records `patchIntake`: the fraction of adjacent painted vertices whose winning source pair changes, excluding holes and unresolved art. It flags places to inspect, not maps to smooth. For release record the composition decision, reference hashes, named grid windows, corresponding mounted cameras and local limits in the terrain ledger. The mounted adapter measures the **actual bound coverage** and replays the previous layout with donor, camera, light, weather and troops held fixed. Keep `<view>-previous.png` alongside original/remaster/restored. In `patchAudit` record boundary fraction, vertices in small same-family patches (≤4 connected vertices), family histogram and normalized neighbor difference of the weighted scan colors. Mask out intentional built transitions and verify them separately. These are ground-space samples, not percentages of screen pixels. If a natural control is genuinely single-material or the previous layout is being retained, record why rather than manufacturing variation.

`fit` checks the controls and puts the images on the review board. Reject a tidy score if the result is a blurred wash, an arbitrary stripe, tiled noise or vegetation floating above a surface it doesn't belong on. Check donor detail and displacement in the close pan. Record what the design fixes **and what still looks different from the reference**. Yavin's brush radii, routes, donors and acceptance limits are not defaults for other planets.

### Ground material variation

Check **two scales** before accepting a reused family. At squad height, find a distinctive stone, groove or print. Pan forward and sideways: does it stamp in rows, form triangular quilts, or swim with the camera? At command height, look *inside* a continuous field rather than counting a cliff or paved road as variation. Compare two regions and the exterior join under the actual weather. Inspect matched prior/remaster and a close pan; a weaker repeating pattern obtained by blurring grain isn't a fix.

For new terrain ledgers set `composition.variation` with `process` (what deposits, erodes or compacts here), `preserve` (the intentional edge or aligned control), a `pair` of **raw TED slots already in `channels`** bound to two different natural scans of that substrate, and a locally chosen `minSpan` (0–1). The mounted checker measures the first scan's share within that pair on the actual uploaded field in both named windows. It excludes holes, authorized built ground, and locations where the pair accounts for less than 70% of coverage. `fit` rejects too little p10–90 spread, insufficient support, adjacent changes large enough to turn the spread into speckles, or the same broad mix returning twice at a regular spacing after a substantial intervening change. It replays the masked, quantized regional samples from the report; short windows cannot rule out a map-wide pattern. If genuinely single-material, supply `uniformReason` and its place-view `evidence` hash instead of a pair; keep the micro and visual checks. Never add rock to flat snow or randomize a slab joint just to pass.

`fit` also tests each verified donor's cooked mip with the terrain chart against the intentionally repeating scan. It checks one- and two-repeat offsets along both UV axes plus a diagonal, and retained detail contrast; manufactured materials must remain aligned. This offline check does **not** see the framebuffer. The HUD-on images remain the check for rows, orientation changes, identifiable repeated objects, blend seams, and mismatched scale after lighting and mip selection. Pick physical scales and local material responses per map rather than copying Hoth's field onto a jungle. A reused source hash is not a reused visual approval.

## Surface and border checks

A plausible still is not a surface test. The plan records `surfaceIntake` (actual water mode and baked shade range/count). Pick a **visible** forest/battlefield boundary, not the sky, HUD or unexplored region. At fixed camera/light, isolate ground shade, visibility, shadows and the water sheet separately. Preserve intentional dark foliage and never reveal the map to fix a black border. On liquid maps capture water-on and bed-only with the same shore and depths; separate lava and ice from liquid. On dry maps verify that no sheet exists. Audit the actual cooked texture bytes: signed U/V normal components must not systematically oppose the associated height slopes. Use two low-angle views a short pan apart and test the shared material edge with different opposite corners. A passing triangle count alone cannot establish depth or continuity.

`fit` now requires `surfaceAudit` alongside the composed shots: `waterMode`, `hasSheet`, an `edgeView` with its selected pixel rect, largest dark-island fraction and reviewed limit, two distinct `surfaceViews`, local `heightRange` at each view and `donors` from `tools/remaster/surface-audit.mjs` (or an explicit retained-material reason). A visible liquid sheet requires `lake` evidence from matched sheet-on/bed-only pixels. See `tools/check-yavin-remaster.cjs` and `tools/check-ultra-daylight.cjs` (`DAY_WATER_AUDIT=1`). `MIXED_SURFACES=1 node tools/check-terrain-shade.cjs` probes actual shader samples for the baked-shade and mixed-edge regressions. These are selected daylight controls, not a rule that night battles or black volcanic stone must be bright.

## Diagnose from the battle

| Symptom seen in play | Fast isolation | Remaster acceptance |
| --- | --- | --- |
| Dirt on what should be grass; forest appears carpeted | Inspect winning RGB/bump pairs **and** where each is painted. Compare open, under shrubs, on trail and at a build site. | Materials match habitat and scale. Forest litter under canopy need not replace an open meadow. Retain a mod's authored alien biome. |
| Rows repeat, ground looks stamped | Look along the route at squad height and down from command. Check donor pattern at one-tile offsets and UV physical scale. | Vary sampling in world space; transform normals, roughness, displacement and mip gradients with albedo. Hard paving can remain regular. Keep relief seams closed and simulation heights unchanged. |
| Shiny bark, black or spiky distant plants | Isolate opaque bark vs alpha foliage, normal-map wrap and roughness/gloss convention; check GPU instance attributes, cutaway and near/far handover. | Trunks, leaves and armor respond differently; real silhouettes at both heights. No gameplay structure replaced as a plant. |
| Flat planet light, floating troops, missing crown shadows | Check actual sky readback vs draw uniforms; inspect sun-caster submission independent of camera cutaways, cascade coverage and texel pitch. | Authored sky and weather drive fill; tight contacts at boots and wider crown shadows without artificial rims or a global grade. |
| Green lake, black zigzags, drips in clear weather | Inspect the ground with **only the water sheets hidden**; distinguish submerged contact shading, authored water/lava level, dry bank and wet foliage. Follow the real forecast through liquid rainfall and clearing. | Lakebed and dry bank suit this planet (not necessarily Endor mud); preserve shoreline depth, paths, fog of war, timing. Lava, ice and disabled water have separate semantics. |
| A shader loads but nothing changed | Wait for compiled/linked ground and submitted pipelines. Inspect actual draw in the deployed camera. Compare original/trial/restored while the sim clock is frozen; then tour in motion. | No-effect and failed rollback stay blocked. Switching off restores the winning art and prop visibility. A prettier still is not a playable release. |

## Route branches

- **Ordinary land Instant Battle:** stock and single-primary profiles use the board's exact source and TED. If search groups an alias under another world, pass `--world "Tatooine Fall of the Republic land"`. No match is a blocker, never permission to capture a similarly named planet.
- **Saved multi-item orders / mission-only, campaign, custom and nested maps:** catalog/plan their installed paths. For composed acceptance, mount the exact saved order through Workshop and start the real mission/campaign/custom route; record order, revision, actual virtual path/hash and HUD-on evidence. The current capture CLI does not launch those routes. Browser-folder overlays, uninstalled dependencies and generated maps aren't inferred by the disk scan.
- **Space:** catalog separately; no terrain jobs, sand substitution or forest placement. Pilot against its real starfield, authored celestial light, nebulae, asteroids, station/ship scale and tactical silhouettes; preserve navigable lanes, build points, fog of war and HUD. A space capture/recipe adapter is future work. Land success is not evidence for a space release.

The first playable mixed-material recipe outside Endor is [stock FoC Yavin 4](yavin-remaster.md), with paired launcher links, preserved temple geometry, zone-limited scanned paving and a reference-led broadleaf canopy and understory.

## Pilot evidence on this installation

The full land plan took **104 seconds** for **3,035 map/load-order combinations** (both stock editions, six installed primaries and two distinct saved multi-item orders); 2,231 distinct painted source pairs. These numbers measure indexing and grouping, **not finished remasters or a production throughput estimate**. Mounted auditions on stock Tatooine and Fall of the Republic's Ambush at Mos Eisley exercised WebGPU and WebGL and checked rollback. An initial GL run showed sky behind units instead of terrain: the trial correctly failed on no visible surface change; the harness now waits for the actual linked ground program before freezing. A sand donor which passed the technical test was recorded as a poor fit for Tatooine's smooth warm lane. No new battle look was enabled by that test.
