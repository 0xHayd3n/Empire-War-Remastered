# Replacement decision: acceptance protocol

A faster incorrect fall doesn't count. Replacement requires passing the current game's visible behavior gates, releasing native constraints/colliders/bodies, and a repeatable player-facing frame-time advantage in the demanding land workload. For this decision, a practical frame-time win means at least 10% lower median or p95 **full-frame** time in both run orders, with no material regression in the other statistic or existing workloads. If the faster solver just buys unused frame budget, retain the existing single engine. Do not infer a defect in either physics library solely from a test integration failure.

- **Quality:** six stock Stormtroopers/Rebel troopers in mounted Universal. Four overlapping at the blast and two outside it. Inspect all referenced skin vertices, triangle edges, head rotations and native socket positions for 180 consecutive 60 Hz steps. Apply the existing crowded-blast test's adversarial velocities. Existing bounds: neck <0.6 rad, joint gap <0.45 game units, upward torso excursion <3, max skinned triangle edge <17. Resting rendered skin clearance −0.2 to +0.7 per casualty, including the final parked pose. Report worst transient clearance separately: the current shipped Rapier correction is bounded and doesn't guarantee no momentary clipping under the artificial impulse. Verify independent detached motion, one native joint lost per detached limb, normal limbs remain attached, drawn poses persist without physics, turning off persistence clears visuals.
- **Performance:** separate from the expensive quality probes. Same input poses from actual stock death events, same camera, map, 24 casualties/240 dynamic bodies/216 initial joints, same blast and exact fixed step. Confirm a main-camera mesh submission. Measure 120 presented frames per leg during the active fall (before parking); report entire frame, full ragdoll update including Three.js skin sync, and the solver alone. Paused-game background controls the rendering workload. Repeat with game logic running (live windows needn't be bit-identical). Counterbalance engine and start order. Record additional ordinary-size (six-body) trials if needed to distinguish stress gains from routine play. No Jolt in the player bundle, no frame-time measurements from synthetic boxes substituted for game tests.
- **Churn and CPU pressure:** replay mounted poses for 24 waves of six casualties in one physics world (144 total): check for zero native resources after each wave, eviction at the 128-visual cap and clearing the saved poses. A repeat with Chrome's 4× CPU throttling stresses a CPU-limited frame; it is not an actual low-spec device or GPU. Report engine creation or spawn costs separately; do not pass off timed post-creation frames as the cost of a whole battle.
- **Limitations:** local headless Chrome/WebGPU and one hardware class; body labels refer to cosmetic casualties only. The previously measured modded fleet and vehicle contact results remain separate. Neither this run nor that test qualifies multiplayer-authoritative physics or a long-session soak on customer hardware.
